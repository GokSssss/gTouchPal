# Описания проектов и выпусков

Правила владельца от 15.11.2026. Основа — [общий журнал новых функций](https://drive.google.com/file/d/1d7utMdLkdiwR321UenGIRro9yxXhJUlt/view). Это правила для авторов, а не текст для страницы приложения.

## README

- Начните с понятного назначения приложения и ссылки на скачивание.
- В блоке **Что умеет** опишите действующие возможности короткими пунктами. Одна самостоятельная функция — один пункт.
- В блоке **Новое в версии** оставьте только заметные добавления, изменения и исправления этой версии.
- Короткую инструкцию добавляйте, только если без неё трудно воспользоваться функцией. Подробные шаги вынесите в отдельную инструкцию.
- Сохраните нужные ссылки, авторство, языки и скриншоты. В русской и английской версиях должны совпадать факты.

## CHANGELOG и GitHub Release

- Заголовок — версия и понятное название изменения.
- Каждый пункт сообщает, что появилось, что изменилось, что исправлено или что убрано.
- Пишите о поведении приложения: «схема помещается на горизонтальном экране», «выбранная кнопка заметно выделяется».
- Не создавайте отдельный пункт ради пересборки, публикации, количества тестов или переноса файлов.
- Существующие функции не выдавайте за новые. Не обещайте исправление сбоя, если именно этот сценарий не подтверждён.
- Установку, отметку **Проверочный выпуск** и необходимое условие доступа укажите отдельно и коротко.
- Не заполняйте заметку общей справкой о приложении: она уже есть в README.

## Что оставить в технических документах

- Количество тестов и классов, отчёты сборки и проверки на эмуляторах.
- SHA, сертификаты, размеры файлов, package/versionCode, SDK/API.
- Имена внутренних классов и методов, детали кода и причины организационных операций.
- Сведения о ключах, подписи, составе архивов, повторном скачивании и публикации.
- Схемы Mermaid, команды и длинные пошаговые сценарии.

Эти материалы сохраняйте в паспорте, техническом журнале и документации для разработчика. Не подмешивайте их в пользовательские описания.

Номера версий приложения, версия Android для совместимости, число доступных вариантов и время удержания кнопки допустимы, когда они нужны пользователю для действия. Статистика разработки не заменяет описание функции.

## Проверка перед сохранением

- Для каждого пункта понятно, что меняется для пользователя.
- Текст подтверждён текущим журналом функций и фактическим выпуском.
- Нет общих фраз вроде «улучшена работа» без конкретного результата.
- Нет дубликатов и старых инструкций, противоречащих текущей версии.
- Ссылки ведут к нужному выпуску, языку и файлам.
- Описания читаются на телефоне коротким списком без горизонтальной прокрутки.

Изменение описаний не требует нового APK. Сохраняйте теги, бинарники, подпись и опубликованные SOURCE. Техническая история остаётся доступной отдельно.
